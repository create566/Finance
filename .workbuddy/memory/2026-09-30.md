## 「管理端删不了会话历史 / 模型不能删除」排查与修复

**结论：两个问题都不在后端，后端删除接口本来就是对的，是管理端前端的三个缺陷。**

### 问题 1：管理端"删不了会话历史"
- 页面实为 `views/chat/record.vue`（菜单名「咨询记录」，不是「会话历史」）。
- 根因：`fetchList()` **完全不传分页参数**，而后端 `AdminChatSessionController.list` 的
  `pageSize` 默认值是 **10** → 前端永远只拿 10 条、也没有 `<el-pagination>`。
  删掉一条后第 11 条顶上，看起来像"没删掉"。库里实际 28 条。
- 修复：加 `pageNum/pageSize/total` 状态 + `<el-pagination>`，`fetchList` 显式传参；
  删/筛后若 `pageNum > maxPage` 自动回退最后一页重拉；序号用 `:index="indexMethod"` 跨页连续。
- 顺带修掉相邻真实缺陷：`ChatSessionDoc` **没有 messages 字段**，列表行不含消息体，
  原 `openDetail` 直接 `detailData = row` → 弹窗气泡区永远空。改为调 `getChatSessionDetail(id)`
  取 `{session, messages}`，加 loading 与 `el-empty`；时间用 `fmtTime` 兼容 ISO 串与 Jackson 时间戳数组。

### 问题 2：【模型配置】不能删除模型
- 后端 `removeConfig` 会拦"被 `ai_chat_model_binding` 引用"的模型（含**已停用**的绑定），
  报 400「该模型已被「对话模型选择」的【…】引用」。这是**正确的**，不是 bug。
- 真 bug 在前端：`model/list.vue` 的 `handleDelete` 里有一条**后端并不存在的假规则**
  `if (row.isDefault === 1) → '默认模型不可删除'` → 默认但未绑定的模型在 UI 上永远删不掉，
  而 API 其实允许。用户就卡在这。
- 修复：
  - 后端 `ModelConfig` 加 `@TableField(exist=false) usedBy / activeUsedBy`；
    `ModelConfigServiceImpl.listAll` 末尾 `fillUsage(list)` ——
    一次 `selectAllForAdmin()` 分组（避免 N+1），`usedBy`=全部引用场景名，`activeUsedBy`=仅启用中的。
  - 前端 `ModelConfig` 接口加同名字段；列表「模型名称」列加「被引用」标签（启用中=warning、仅有停用引用=info）+ 场景名 tooltip；
    删除按钮被引用时 `disabled` 并给 tooltip 说明；`handleDelete` 兜底用 `usedBy` 提示（替换掉 isDefault 假规则）；
    编辑弹窗「启用状态」旁在被 `activeUsedBy` 引用时提示"停用会被拒绝"。
- 前端 `api/modelConfig.ts` 的 `ModelConfig` 同步加 `usedBy/activeUsedBy`。

**改造的既有文件（3 个签署关口）**
- `LendServiceImpl.createLend()` → 建标时预生成《借款合同》；`publish()` → assertSigned(LOAN) + 预生成《放款确认书》
- `LendItemServiceImpl.buildInvestForm()` → 在"校验投资金额"与"校验余额"之间插 assertSigned(INVEST, amount)
- `LendReturnServiceImpl.buildMakeLoanForm()` → 在幂等检查后插 assertSigned(PAYMENT)
- `AdminLendController.create()` → 该接口绕过 publish 直接置募资中，补上两类合同的预生成

**关键设计决策（血泪换来的）**
1. **出借协议的唯一键必须含 `amount`**：`uk_biz(biz_type,biz_id,contract_type,party_a_id,is_deleted,amount)`。
   最初只含前 4 列，导致"改金额要重签"时只能软删除旧行 → 第二条软删行撞唯一键。
   现在金额是合同身份的一部分：换金额 = 换合同 = 新插一行，永不软删。
2. **不要在 `@Transactional` 方法里 catch 掉 inner `@Transactional` 的异常**：`createLend` 里若 try-catch 吞掉 `getOrCreate` 的异常，内层事务已标记 rollback-only，外层提交会抛 UnexpectedRollbackException。所以预生成直接抛，不做兜底。
3. **`sign()` 内部调 `doPersistSign()` 属自调用，`@Transactional` 失效** → 改用 `new TransactionTemplate(transactionManager).execute(...)` 编程式事务。
4. 签名图先上传（外部 IO）再开事务写库。
5. 幂等三层：`findOne` 读后复用 + `sign` 前查存证 + `uk_contract_signer(contract_id,signer_id)` 兜底。
