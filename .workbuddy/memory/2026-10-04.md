## 修复：api 启动被银行库(BankHikariPool)连接超时拖垮

**现象**：`DemoApplication` 启动失败，退出码 1。`BankHikariPool` 初始化时
`Communications link failure / Connection timed out`，异常链一路冒泡到
`adminBorrowInfoController → borrowInfoService → lendService → lendItemService →
userAccountService → bankAccountSyncService → bankJdbcTemplate`，整个容器 refresh 取消。

**排查结论（重要，别再误判）**：
- 银行库在**阿里云 RDS** `rm-uf6ry261ghx3995253o.mysql.rds.aliyuncs.com`（解析到 106.15.168.220），
  库名 `ww_bank`，表 `user_account`（`user_code / amount / freeze_amount / is_deleted`），139 行。
- 用 mysql 客户端与 Python 直连 RDS **都通**；写一个单文件 Java 探针跑 JDBC 也 **OK（697ms）**。
  → 说明那次是**瞬时网络抖动**，不是凭据错、不是 RDS 释放、不是代理拦截
  （虽然堆栈里出现过 `SocksSocketImpl`，但实测并非主因，不要被它误导）。
- 真正的缺陷是**设计层面**：Hikari 默认是 eager fail-fast，一个**只读旁路镜像库**抖动
  就整站起不来，而 `BankAccountSyncServiceImpl` 早就写好了降级到平台 `user_account` 的逻辑
  —— 降级根本没机会执行。

**改法**（`api/src/main/java/com/example/demo/config/BankDataSourceConfig.java`）：
- `config.setInitializationFailTimeout(-1)` → 启动不预建连接，`checkFailFast()` 直接返回。
- `setConnectionTimeout(8000)` + `setValidationTimeout(3000)`，避免业务调用被默认 30s 卡死。
- 新增可配 `bank-datasource.connect-timeout-ms`（默认 8000，yml 里 `BANK_DB_CONNECT_TIMEOUT`）。

**验证（两条路径都实测过）**：
- 正常：8991 起来 → 提现超额返回 `当前可用 ¥-650.60`（= 银行侧值）。
- 降级：故意指向不可路由 IP `10.255.255.1` → 服务**照样启动**（改前必崩），
  余额自动回落到平台侧 `4349.40`。
- 判别器很好用：user 42 银行侧 `-650.60` vs 平台侧 `4349.40`，两个数差异明显，
  看"提现超额"文案里的数值就知道走了哪条路。
- 自测进程（8991/8992）已 TaskStop 杀掉并确认端口释放；临时探针 `_probe_jdbc.java` 已删。

## 修复：满标后资金无限期悬停（资金池风险）—— 已实现并验证

**问题（很严重，之前没人发现）**：标的满标 → 借款人不签《放款确认书》→ 投资人资金冻结在银行，
而**三条退路全被堵死**：
- `failLend()`（`LendServiceImpl:280`）只扫 FUNDING，满标待放款(COMPLETED)不管
- `offline()`（原 `:117`）只认 PENDING/FUNDING，管理员手动下架都点不动
- `cancelInvest`（`LendItemServiceImpl:351`）拒绝 status=2 的记录，投资人自己也撤不了

⇒ 资金无限期悬停，实质是资金池风险，属合规红线。

**还有一个隐藏更深的坑**：`withdrawAllInvestments` 原来只捞 `lend_item.status = 0`，
而满标时 `LendItemServiceImpl:321` 会把该标的全部投资统一置为 **2**。
**光放开 `offline()` 的状态准入而不改这个查询，退资会静默空跑** —— 一笔都退不掉且无任何报错。
这两处必须成对改。

**改了什么**（4 个后端文件 + 1 个前端）：
1. `LendServiceImpl.withdrawAllInvestments` — 撤标范围 `status=0` → `IN (0, 2)`
2. `LendServiceImpl.offline` — 准入加 `COMPLETED`（注意：**不含** REPAYING(5)/SETTLED(6)，
   放款后的标的绝不能退资，账目会对不上）
3. `LendServiceImpl.createLend` — 建标即预生成《放款确认书》（原来只在 publish 时生成，
   借款人根本无从提前签起）
4. `LendServiceImpl.publish` — 新增签署关口二：`assertSigned(PAYMENT)`，
   上架前签齐《借款合同》+《放款确认书》⇒ **满标必然可放款**，从源头消灭悬停
5. `MessageTypeEnum` 新增 `MAKE_LOAN_PENDING(30, "满标待签确认书")` +
   `MessageService.sendMakeLoanPendingNotice`，在 `LendItemServiceImpl` 满标分支给借款人催签
6. 前端 `ww_finance_user/src/api/message.ts` 的 `MESSAGE_TYPE_META` 加 30

**验证**：`api` 编译 BUILD SUCCESS；离线 Mockito 白名单 **Tests run: 75, Failures: 0**
（原 74，新增 1 个）；`ww_finance_user` 的 `vue-tsc -b` 零输出。
新增测试 `offline_completedLendWithSignedItems_refundsStatusTwoItems` 专门钉住"status=2 也要退资"。
原 `offline_illegalStatus_throws` 断言的正是"COMPLETED 不可下架"，已改为用 REPAYING(5) 做非法用例。

**没做、且应作为后续项**：
- `offline()` 没有 `adminId` 参数，处置投资人资金**没有操作人留痕**。
  `AdminLendController` 里有现成的 `currentAdminId()`，但 `Lend` 表没有"下架人/下架时间"列，
  复用 `checkAdminId/checkTime`（发布审核）语义会串。要补得先加列。

  没有条款就自动退资本身是新的合规风险。现在靠"催签通知 + 人工出口"已经足够。

## 自我纠错：撤销「publish 强签《放款确认书》」，改回"满标后放款前签"

**推翻上面第 4 条**（`LendServiceImpl.publish` 加 `assertSigned(PAYMENT)`）——
用户追问"签合同的时机是否符合国家规范/社会共识"后复查，认定该改动**法理不通**：
《放款确认书》是"确认放款、授权划款"的意思表示，标的还没募满就要求借款人确认放款，
逻辑上站不住，也不符合行业惯例。**已回滚为 `getOrCreate(PAYMENT, ...)`**（仅幂等预生成，
借款人在募资期可自愿提前签，避免满标后卡住），硬校验保留在
`LendReturnServiceImpl.buildMakeLoanForm` 的**签署关口三（满标后、放款前）**。
`createLend` 的预生成**保留**（否则借款人无从提前签起）。

资金悬停风险改由**三条措施**兜住，而不是靠提前强签：
① 满标即发催签站内信 `MAKE_LOAN_PENDING(30)`；
② `offline()` 放开 `COMPLETED` + `withdrawAllInvestments` 覆盖 `status IN (0,2)`（资金不会被永久冻结）；
③ 合同模板写入超期处置条款（给处置提供事先约定依据）。

### 合同模板补超期处置条款（新增 `sql/contract_overdue_clause.sql`，已执行）
走模板版本化机制：`TPL_LOAN` / `TPL_INVEST` 各新增 v2 并启用，v1 置 `status=0` 退役；
`TPL_PAYMENT` 未动（仍是 v1）。已签署合同靠 `content_snapshot` 冻结，改模板**不影响历史合同**。
条款要点：**满标后 3 个自然日内签《放款确认书》，逾期平台有权终止撮合 + 通知存管银行解冻 + 原路退回**。

⚠️ **MySQL 字符串里 `'\n'` 是真换行，不是字面反斜杠-n**（`NO_BACKSLASH_ESCAPES` 默认关闭）。
一开始写成 `'\\n'`（两个字符）导致模板里出现字面 `\n`，已用
`REPLACE(content_tpl, CONCAT(CHAR(92),'n'), CHAR(10))` 就地修正。
核查手法：`CHAR_LENGTH(x)-CHAR_LENGTH(REPLACE(x,CONCAT(CHAR(92),'n'),''))` 应为 **0**。
另外 MySQL 里 `||` 是**逻辑或**不是字符串拼接 —— 写 `LIKE '%' || CHAR(92) || '%'` 会静默变 OR，必须用 `CONCAT()`。
落库结果：TPL_LOAN v2(442字)/TPL_INVEST v2(498字) status=1，backslash_n 均为 0。
