### ⚠️ PowerShell 5.1 的 .ps1 编码坑（本次真踩到）

用**无 BOM** 的 UTF-8 写 `.ps1`，PS 5.1 会**按 GBK 解码** ⇒ 中文注释被拆成乱码 →
`表达式或语句中包含意外的标记` / `字符串缺少终止符`，**整个脚本语法失败**。
判据：报错里出现 `Write-Host '[ok”。` 这类被截断的字符串。
**修法：`.ps1` 必须存成 UTF-8 带 BOM**：
`printf '\xEF\xBB\xBF' | cat - f.ps1 > f.new && mv -f f.new f.ps1`。

### ⚠️ 非登录 shell 缺 coreutils（真实风险，未能在沙箱验证）

`bash manage.sh` 属于**非登录 shell**，不加载 Git Bash 的 `/etc/profile`；PATH 里若没有 Git 的 `usr\bin`，

**更隐蔽的是 `cygpath` 缺失**：`native_path()` 会退化成恒等、`pid_of()` 静默改走 Linux 分支
（`pgrep` 看不到原生 java.exe）⇒ **`status` 显示的 DOWN 是假的、`stop` 也停不掉进程**。
故 `start-all.ps1` 前置 `/usr/bin:/bin;D:\Git\usr\bin;D:\Git\bin;$env:PATH`。

（沙箱内**无法复现/验证**：该环境 PATH 被运行框架强制接管，`$env:PATH` 赋值被覆盖；

### 沙箱排障技巧（复用）

PowerShell 工具的 stdout 在本会话不可见 ⇒ **把输出 `*>>` 重定向到文件，再用 Read 或
`tr -d '\000' < f` 读**。注意 PS 5.1 的 `>>` 默认写 **UTF-16LE**，与 `Out-File -Encoding utf8`

## 11:4x 公网 frp 访问（120.26.132.5:81）登录 403：**网关 CORS 白名单不含公网 Origin**

**架构**：别人电脑 → 阿里云 nginx:81 → frp → 本机 Vite dev(5173) → Vite proxy `/admin|/api|/ai` → 本机网关 8088。
页面正常、登录 POST 返 **403**。

**锁定过程（读代码实证，非猜测）**：
- 前端 `request.ts` baseURL = **相对路径** `/admin/core`（+ AI 实例 `/ai/admin`）⇒ 请求与页面同源（都走 :81），
  **浏览器无需预检**，但 POST 会带 `Origin: http://120.26.132.5:81`。
- Vite proxy `changeOrigin: true` **只改 Host、不改 Origin** ⇒ 公网 Origin 原样到达网关。
- 网关 `CorsConfig.java`（finance-gateway/.../config/）白名单**硬编码**仅 4 个：
  `localhost/127.0.0.1 × 5173/5174` ⇒ 公网 Origin 不在表内 → Spring Cloud Gateway `CorsWebFilter`
  拒绝 → **403 Forbidden（响应体 "Invalid CORS request"）**。
- 已排除 api 侧：`SecurityConfig.java` `csrf().disable()` + `anyRequest().permitAll()`，无 Origin 拦截器 ⇒ api 不可能产 403。

**为什么本地好、公网 403**：本地页面 Origin=`http://localhost:5173` 在白名单内；公网页面 Origin=`http://120.26.132.5:81` 不在。
**为什么能拿到 403 而不是 502**：请求确实穿透到了后端（Vite proxy 是服务端转发）——「后端没 frp 隧道」的说法对该架构**不成立**。

**修法（两选一）**：
1. 网关白名单加一行 `config.addAllowedOrigin("http://120.26.132.5:81")`（含 5174 用户端将来暴露的公网地址）→ **重打 gateway jar**。
2. 不动后端：`vite.config.ts` 各 proxy 加 `headers: { Origin: 'http://localhost:5173' }` 覆写 Origin（http-proxy 的 headers 会覆写既有头）→ 只需重启 npm。
**更优长期**：白名单改从 yml/env 读（`addAllowedOriginPattern`），部署换域名免重打。
**验证指纹**：403 响应体含 **"Invalid CORS request"** 即网关 CORS 拒绝，浏览器 Network 看请求头 `Origin: http://120.26.132.5:81`。
