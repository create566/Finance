# ww_finance 接口测试使用说明（Postman + JMeter）

> 更新：2026-10-09 ｜ 目标：`http://localhost:8990`（api 直连；也可换成网关 `http://localhost:8088`）

## 一、Postman：导入即跑，不用管 token

| 文件 | 说明 |
|---|---|
| `docs/postman/ww_finance.postman_collection.json` | 集合：**104 请求 / 12 目录**，覆盖全部 103 个接口 |
| `docs/postman/ww_finance.postman_environment.json` | 环境：`baseUrl` + 三组账号 |

**操作**：Postman → Import → 把上面两个 json 拖进去 → 选中集合点 **Run**（或单个请求 Send）。

**Token 全自动**（集合级 Pre-request 脚本已内置）：
- 每个请求发出前，脚本判断对应身份的 token 是否存在 / 是否将过期（解析 JWT `exp`，**提前 60 秒**刷新）；
- 缺失或过期就自动调登录接口拿新 token 写回集合变量；
- 某个请求万一返回 401，Test 脚本会清掉 token 并**自动重放一次**（自愈）。

**三套 token 各走各的头**：管理端 `token` 头；用户端 `Authorization` 头；投资人另加 `X-Api-Scope: investor`。

|---|---|---|

⚠️ **只有 BCrypt 存储的账号能登录**，库里明文/MD5 的老账号会报「密码错误」。

⚠️ **`/admin/core/logout` 和 `/api/user/logout` 会清 Redis 登录态**，跑完它们后面的请求会全部 401 —— 单独验证时再手工执行。

#### 两轮实测结果

| 轮次 | 范围 | 用例 | 通过 | 未通过 | 通过率 |
|---|---|---|---|---|---|
| 只读轮 | 仅只读接口（写操作跳过 46） | 104 | 58 | 0 | **100%** |
| **全量轮（含写操作）** | **105 条全部真实执行** | 105 | 90 | 15 | 85.7% |

> 全量轮未通过的 15 条**全部是前置条件/数据/环境不满足**，不是接口缺陷：
> 标的状态不允许（无「待发布」标）、库里没有「待审核/认证中」记录、实名与借款申请缺身份证影像等必填材料、
> 投资人未签《出借协议》、借款人未签《资金存管协议》、两个测试账号**银行可用余额为 0**、
> **存管银行 9090 未启动**（放款返回「银行无应答」）。
> 补前置条件的推荐顺序：签协议 → 充值 → 投标/还款。

> ⚠️ **写操作会真改库**。全量轮前已用 `mysqldump` 全量备份（`.workbuddy/tmp/backup_ww_finance_*_pre_write.sql`），
> 跑完把被测试误改的**合同模板版本**与**测试字典**清理回原状；积分等级的「新增/修改/删除」用例已改为
> 只操作**自己新建的那一条**（新增接口只返回 `data=true`，故补了一次「分页回查取最大 id」）。

## 二、JMeter：QPS 压测

文件：`docs/jmeter/ww_finance_benchmark.jmx`

- **SetupThreadGroup** 先用三个身份登录，把 token 写进 JMeter 全局属性（`props.put`）→
  主线程组用 `${__P(adminToken)}` / `${__P(userToken)}` / `${__P(investorToken)}` 读取，**同样不用手工贴 token**；
- **场景一**（默认启用）：混合只读接口，默认 20 并发 / 10s ramp-up / 120s，可在 JMeter 属性里覆盖；
- **场景二**：登录接口吞吐（默认禁用，需要时手动启用）。

命令行跑（自动出 HTML 报告）：
```bash
jmeter -n -t ww_finance_benchmark.jmx -l result.jtl -e -o report
```

⚠️ **只压只读接口。** 充值/提现/投标/还款/放款**绝不能压**：银行侧 `recharge`/`withdraw` **没有幂等去重**，重复提交会重复入账，直接产生脏数据（`vote`/`makeLoan` 有去重）。

## 三、测试发现的真实问题（非脚本问题）

| 接口 | 现象 | 说明 |
|---|---|---|
| `POST /api/core/contract/auth/prepare` | **500 泄露 SQL** | 调用者不是该标的借款人时，唯一键 `uk_biz` 冲突直接抛库异常，`msg` 里带出 `SQLIntegrityConstraintViolationException` 与 Mapper 类名 —— 敏感信息泄露 + 未做友好拦截（应为 403）。根因：`findOne()` 用「调用者 userId」当 `party_a_id` 查重，而 `fillParties()` 把 LOAN/PAYMENT 甲方写成「借款人 id」，两者不一致 → 查不到 → 插入 → 撞键。**建议修复**。 |
| `GET .../dict/listByCode` | 500 | 参数名是 **`dictCode`**（不是 `code`）；缺失/写错时返回 `500 系统内部错误` 而非 400。可用值：education/industry/income/relation/returnMethod/returnSource/moneyUse/borrowStatus/SchoolStatus。 |
| `POST /admin/core/dict/category` | **静默建脏数据** | 后端取 body 的 `dictCode`（**不是 `code`**）；传 `code` 不报错，会建出 `dict_code=NULL` 的脏分类（已实测复现）。**建议加参数校验**。 |
| `PUT /admin/core/dict/update` | 500 | 撞唯一键 `uk_parent_id_value(parent_id,value)` 时返回 `500 系统内部错误`，msg 无有效信息。 |
| `PUT .../contract/template/{id}/status` | 500 | `status` 是 **query 参数**（`@RequestParam`），放 body 里会 500；且该方法 catch **只捕获 `ResourceNotFoundException`**，其它异常一律冒泡成通用 500。 |
| `GET /api/core/chat/message/list` | 403（正常） | 查非本人会话返回「无权访问他人会话」—— **越权修复后的正确行为**，不是缺陷。 |
| 充值 / 提现 / 还款 / 投标 | HTML | 业务成功时返回**银行 HTML 表单**（跳存管银行确认页），不是 JSON；失败却是 `200 + {"code":400}`，前端靠 `parseErrorEnvelope()` 区分。 |

> 另有 3 条**参数坑**（不是后端缺陷，但很容易踩）：`积分等级` 实体字段是 `integralStart/integralEnd`（不是 min/max，也没有 gradeName）且区间不能与已有档位重叠；
> `字典项` 的 `value` 必须是 **Integer**；`客服消息` 的 `role` 必填（user/assistant）。

## 四、改了接口后怎么重新生成

```bash
cd docs/postman && python generate_collection.py
```
生成器从 Controller 源码提取端点（`@GetMapping` 等）生成集合；改动接口后重跑即可，无需手维护 json。
