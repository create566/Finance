# 服务器部署与测试方案

> 生成于 2026-10-09。适用于把本项目从本机（Windows + IDEA）迁移到一台 Linux 服务器。
> 关键结论：**上传 6 个 jar**，服务器需装 **两套 JDK**，有 **3 处硬编码地址必须改**。

---

## 一、要上传的产物

### 1.1 后端 jar（6 个）

| # | 产物（打完后） | 端口 | 说明 |
|---|---|---|---|
| 1 | `api/target/api-1.0-exec.jar` | 8990 | 核心业务，约 75 MB |
| 2 | `finance-gateway/target/finance-gateway-1.0-exec.jar` | 8088 | 网关，前端唯一入口 |
| 3 | `finance-message/target/finance-message-1.0-exec.jar` | 8120 | 短信 |
| 4 | `finance-oss/target/finance-oss-1.0-exec.jar` | 8130 | 文件 |
| 5 | `finance-ai/target/finance-ai-1.0-exec.jar` | 8081 | AI（**Java 17**） |
| 6 | `ww_bank-1.0.0.jar` | 9090 | 存管银行，**无源码，必须一起上** |

**不要上传** `finance-common` / `finance-base` —— 这两个是库模块，已打进上面每个 fat jar 里。

⚠️ **产物名必须带 `-exec` 后缀**。五个模块的 pom 都配了 `<classifier>exec</classifier>`：
- `api-1.0-exec.jar`（约 75 MB）→ 可执行 fat jar，`java -jar` 能跑
- `api-1.0.jar`（约 466 KB）→ thin jar，**直接 `java -jar` 会报找不到主类**

### 1.2 打包命令

```bash
# 在项目根目录，必须先把库模块装进本地仓库，否则单模块打包取到旧版
mvn -o -B -pl finance-common,finance-base -am install -Dmaven.test.skip=true
# 再打包 5 个服务
mvn -o -B -pl api,finance-gateway,finance-message,finance-oss,finance-ai -am package -Dmaven.test.skip=true
```

（本机 maven 脚本起不来的话，用 java 直启 plexus 启动器，见 skill `finance-demo-build`。）

校验产物是否可执行：

```bash
ls -lh */target/*-exec.jar          # 应有 5 个，最大的 api 约 75 MB
unzip -l api/target/api-1.0-exec.jar | grep -c "BOOT-INF/lib/"   # 应 >100，说明是 fat jar
```

### 1.3 前端（2 个静态站点）

```bash
cd ww/ww_finance_user   && npm ci && npm run build    # 产物 dist/
cd ww/ww_finance_admin  && npm ci && npm run build    # 产物 dist/
```

⚠️ `npm run build` 会先跑 `vue-tsc -b` 做类型检查。**如果因既有类型错误中断，改用 `npx vite build` 跳过检查**（本项目的类型问题不代表运行有问题）。

上传 `dist/` 整个目录，用 nginx 托管。**生产环境没有 Vite 代理**，所以 nginx 必须自己配反向代理：

```nginx
server {
    listen 80;
    root /opt/ww/user-dist;          # 用户端 dist
    location / { try_files $uri $uri/ /index.html; }   # Vue Router history 模式必需
    location /api/ { proxy_pass http://127.0.0.1:8088; proxy_set_header Host $host; }
    location /ai/  { proxy_pass http://127.0.0.1:8088; proxy_set_header Host $host; }
}
```

## 二、服务器需要先装好的中间件

| 组件 | 版本 | 端口 | 谁依赖它 | 备注 |
|---|---|---|---|---|
| Nacos | **2.2.3** | 8848 / 9848 / 9849 | api、gateway、message、oss | **必须最先启动**，注册失败会让这些服务直接启动不了 |
| MySQL | 8.0 | 3306 | api、ai | 库名 `ww_finance` |
| Redis | 7 | 6379 | api、message、oss、ai | 登录态 + 验证码 |
| MongoDB | — | 27017 | ai | 库 `ww_finance_ai` |
| Chroma | **1.0.0** | 8000 | ai | 必须 1.x（Spring AI 走 `/api/v2/*`，0.6.x 只有 v1） |
| **JDK 8** | — | — | api、gateway、message、oss、bank | |
| **JDK 17** | — | — | finance-ai | |

⚠️ **两个 JDK 是硬要求**：`finance-ai` 是 Spring Boot 3.4.8 + Java 17，其余全是 Spring Boot 2.3.4 + Java 8。用 17 跑 Java 8 那批虽能起来，但用 8 跑 finance-ai **必然失败**。

⚠️ **Nacos 不能写账号密码**：本项目的 Nacos 关了鉴权（`nacos.core.auth.enabled=false`），yml 里配 `username/password` 会让客户端每 2 秒重试登录并刷 ERROR 日志。四处配置已清空，**新服务器的 Nacos 若开了鉴权，要么也关掉，要么补上账号**。

## 三、必须修改的配置（部署最容易漏的部分）

### 3.1 硬编码清单

以下**没有环境变量兜底**，不改就一定连不上：

| 位置 | 现在的值 | 服务器上必须改成 |
|---|---|---|
| `api/application.yml:25` | `jdbc:mysql://localhost:3306/ww_finance` | 服务器 MySQL 地址 |
| `api/application.yml:45` | `server-addr: localhost:8848` | 服务器 Nacos 地址 |
| `finance-ai/application.yml:55` | `jdbc:mysql://localhost:3306/ww_finance` | 同上 |
| `finance-gateway/application.yml:17` + `bootstrap.yml:13,23` | `127.0.0.1:8848` | 同上 |
| `finance-message/application.yml:23,38` + `bootstrap.yml:12,25` | `localhost` / `localhost:8848` | 同上 |
| `finance-oss/bootstrap.yml:16,24` | `127.0.0.1:8848` | 同上 |

以下**已有环境变量兜底**，设环境变量即可，无需改配置：

| 配置项 | 环境变量 | 默认值 |
|---|---|---|
| MySQL 用户名 / 密码 | `DB_USERNAME` / `DB_PASSWORD` | root / 123456 |
| Redis 主机 / 端口 | `REDIS_HOST` / `REDIS_PORT` | localhost / 6379 |
| Mongo 连接串（ai） | `MONGODB_URI` | `mongodb://localhost:27017/ww_finance_ai` |
| Chroma 主机（ai） | `CHROMADB_HOST` | 127.0.0.1 |
| 银行服务地址 | `BANK_BASE_URL` | `http://localhost:9090` |
| 银行回调地址 | `BANK_NOTIFY_BASE_URL` | `http://localhost:8990` |
| 前端地址（银行回跳） | `BANK_FRONT_BASE_URL` | `http://localhost:5174` |
| AI 嵌入服务地址 | `AI_EMBEDDING_URL` | `http://localhost:8081/...` |
| 网关的 AI 服务地址 | `AI_SERVICE_URI` | `http://localhost:8081` |

### 3.2 三个特别容易漏的点

**① 注册到 Nacos 的 IP 会是错的**

本机实测注册上去的地址是 `192.168.112.1`（虚拟网卡），不是 `127.0.0.1`。服务器上如果有多个网卡（内网 + 公网 + Docker），Nacos 很可能登记成 **Docker 网桥的 172.x 地址**，导致网关转发到不可达的 IP。

**每个注册进 Nacos 的服务都要显式指定**：

```yaml
spring:
  cloud:
    nacos:
      discovery:
        ip: 10.0.0.6          # 换成服务器真实内网 IP
```

**② 银行回调地址必须是"银行能访问到的"地址**

`BANK_NOTIFY_BASE_URL` 现在是 `http://localhost:8990` —— 银行服务器回调这个地址是打不通的（它指的是银行自己那台机器的 8990）。**必须改成公网可访问的域名或 IP**：

```bash
BANK_NOTIFY_BASE_URL=http://your-domain.com:8990
BANK_FRONT_BASE_URL=http://your-domain.com     # 支付完成后的回跳页
```

**③ 银行库是外网 RDS**

api 连的银行库 `ww_bank` 在阿里云 RDS（配置在 `api/application.yml` 的 `bank-datasource` 段，凭据是明文）。部署前确认：**服务器能否访问该 RDS**（RDS 有 IP 白名单，需要把服务器公网 IP 加进去）。

### 3.3 推荐做法：外置配置，不改 jar

不要为了改配置重新打包。Spring Boot 会**优先加载 jar 同目录的 `config/` 目录**，优先级高于 jar 内部：

```
/opt/ww/
├── api-1.0-exec.jar
├── config/
│   └── application.yml       ← 覆盖 jar 内的同名配置
└── logs/
```

所以每个服务目录下放一份改好的 `config/application.yml`（内容只写要覆盖的项即可，Spring Boot 会合并）：

```yaml
# /opt/ww/config/application.yml（api 用，示例）
spring:
  datasource:
    url: jdbc:mysql://10.0.0.5:3306/ww_finance?serverTimezone=GMT%2B8&characterEncoding=utf-8&useSSL=false
  redis:
    host: 10.0.0.5
  cloud:
    nacos:
      discovery:
        server-addr: 10.0.0.5:8848
        ip: 10.0.0.6
```

⚠️ `gateway` / `message` / `oss` 用了 `bootstrap.yml`（Nacos 注册在 bootstrap 阶段读），**外置目录里也要放 `bootstrap.yml`，光放 `application.yml` 不够**。若发现外置不生效，改用启动参数（命令行优先级最高）：

```bash
java -jar finance-gateway-1.0-exec.jar \
  --spring.cloud.nacos.discovery.server-addr=10.0.0.5:8848 \
  --spring.cloud.nacos.discovery.ip=10.0.0.6
```

## 四、数据迁移

```bash
# 1) 建表（db_init.sql 在项目【根目录】，不在 sql/ 下）
mysql -h10.0.0.5 -uroot -p < db_init.sql

# 2) 结构订正 + 业务补丁（sql/ 目录，按需执行）
for f in fix_schema_drift.sql fix_lend_tables.sql fix_user_mobile_unique.sql \
         fix_repay_plan_balance.sql fix_admin_role.sql contract.sql message.sql; do
  mysql -h10.0.0.5 -uroot -p ww_finance < sql/$f
done

# 3) 存量数据（如果要保留本机测试数据）
mysqldump -uroot -p123456 --single-transaction --default-character-set=utf8mb4 \
  ww_finance > ww_finance_data.sql
mysql -h10.0.0.5 -uroot -p ww_finance < ww_finance_data.sql
```

⚠️ 如果一并迁移存量数据，注意**本机已知的脏数据**（银行负余额、6 条悬挂流水、11 条 `benefit_bind_code='0'`）会一起带过去。**只做演示的话建议只导 `db_init.sql` + 少量测试账号**。

## 五、测试方案（四层，由浅入深）

### 第 0 层：环境自检（不启动任何 jar）

目标：确认中间件都活着、地址都对。

```bash
#!/bin/bash
# 非 HTTP 服务（Redis/MySQL/Mongo）不能用 curl 探测 —— curl 恒返回 000 会误判
check_tcp() { timeout 2 bash -c "echo > /dev/tcp/$1/$2" 2>/dev/null && echo "OK   $3 ($1:$2)" || echo "FAIL $3 ($1:$2)"; }
check_http() { code=$(curl -s -m 5 -o /dev/null -w "%{http_code}" "$1"); [ "$code" != "000" ] && echo "OK   $2 ($code)" || echo "FAIL $2"; }

NACOS=10.0.0.5; MYSQL=10.0.0.5; REDIS=10.0.0.5; MONGO=10.0.0.5

check_http "http://$NACOS:8848/nacos/v1/console/server/state" "Nacos"
check_tcp  $MYSQL 3306 "MySQL"
check_tcp  $REDIS 6379 "Redis"
check_tcp  $MONGO 27017 "MongoDB"
check_http "http://$MONGO:8000/api/v1/heartbeat"            "Chroma"
```

### 第 1 层：启动自检（每个 jar 起得来、注册得上）

启动顺序：**Nacos → MySQL/Redis/Mongo/Chroma → 银行 → api → gateway → message → oss → ai**

```bash
cd /opt/ww
nohup java -jar ww_bank-1.0.0.jar            > logs/bank.log    2>&1 &
nohup java -jar api-1.0-exec.jar             > logs/api.log     2>&1 &
nohup java -jar finance-gateway-1.0-exec.jar > logs/gateway.log 2>&1 &
nohup java -jar finance-message-1.0-exec.jar > logs/message.log 2>&1 &
nohup java -jar finance-oss-1.0-exec.jar     > logs/oss.log     2>&1 &
nohup /usr/lib/jvm/jdk17/bin/java -jar finance-ai-1.0-exec.jar > logs/ai.log 2>&1 &
```

逐个确认：

```bash
# ① 进程与端口
ss -lntp | grep -E ':(8990|8088|8120|8130|8081|9090)'

# ② 是否注册进 Nacos（关键！只看到进程不够）
curl -s "http://10.0.0.5:8848/nacos/v1/ns/service/list?pageNo=1&pageSize=20"
#    期望看到：service-core / service-gateway / service-sms / service-oss

# ③ 注册的 IP 是否是服务器真实内网 IP（不是 172.x / 192.168.x 的虚拟网卡）
for s in service-core service-gateway service-sms service-oss; do
  echo -n "$s -> "
  curl -s "http://10.0.0.5:8848/nacos/v1/ns/instance/list?serviceName=$s" | grep -o '"ip":"[^"]*"'
done

# ④ 启动日志无致命异常
grep -l "APPLICATION FAILED TO START\|PortInUseException" logs/*.log
```

### 第 2 层：接口冒烟（10 分钟跑完）

```bash
GW=http://10.0.0.6:8088      # 网关对外地址

# 1. 网关路由是否通（每个后端一条）
curl -s -o /dev/null -w "core   %{http_code}\n" "$GW/api/core/lend/list"
curl -s -o /dev/null -w "user   %{http_code}\n" "$GW/api/user/hello"
curl -s -o /dev/null -w "sms    %{http_code}\n" "$GW/api/sms/user/sendCode"
curl -s -o /dev/null -w "oss    %{http_code}\n" "$GW/api/oss/file/hello"
curl -s -o /dev/null -w "ai     %{http_code}\n" "$GW/ai/health"
curl -s -o /dev/null -w "legacy %{http_code}\n" "$GW/api/knowledge/files/hello"
# 期望：都不是 404/503。503 = 对应服务没注册；404 = 路由没匹配上

# 2. 登录（Redis 是否可用会在这里暴露）
curl -s -X POST "$GW/api/user/login" -d "mobile=13800001111&password=123456" | head -c 200

# 3. 验证码全链路（api → Feign/Nacos → message → Redis）
curl -s -X POST "$GW/api/user/sendCode" -d "mobile=13800001111"
#    期望 {"code":200,"msg":"验证码已发送"}
#    若报"没有可用实例" → message 没注册 Nacos
#    若报 Redis 连接失败 → Redis 地址没配对

# 4. 未登录访问应被拦（鉴权是否生效）
curl -s -o /dev/null -w "no-token %{http_code}\n" "$GW/api/core/lend/list"   # 期望 401
```

### 第 3 层：业务链路（本项目已在本机完整验证过的闭环）

按顺序手工走一遍，每步核对数据库：

| 步骤 | 操作 | 核对点 |
|---|---|---|
| 1 | 借款人注册 → 绑卡 | `user_bind` 有记录；银行库 `user_bind` 同步 |
| 2 | 提交借款申请 → 后台审批 | `borrow_info.status` 推进 |
| 3 | 后台发标 → 上架 | `lend.status=1`；会自动生成《借款合同》 |
| 4 | 投资人签署《出借协议》→ 投标 | `lend_item` 有记录；银行 `user_invest` 同步 |
| 5 | 满标 → 后台放款 | `lend.status=5`、`payment_time` 有值、生成 12 期计划 |
| 6 | 借款人还第 1 期 | `lend_return.status=1`、`real_return_time` 有值、投资人明细落账 |
| 7 | 投资人看「回款计划」→ 点明细 | 能打开且数据显示正确（对应 P7-51 修复） |

⚠️ **放款有三个前置条件**，缺一个就会失败：
1. **借款人已绑卡**（本机数据里只有借款人 33 绑了卡）
2. 投标表单传了 `benefitBindCode`（已修，别删）
3. 银行侧该标的的 `user_invest` 有记录

⚠️ **还款有银行强等式校验**：`voteFeeAmt + Σ明细 == 期供`，多投资人标的的金额必须自洽（已修，见 P4-53）。
